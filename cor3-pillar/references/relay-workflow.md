# 用 Relay 接手一轮

适用于 COR3 Relay 2.2.1 的 Chrome、Edge 游戏页。当前页没有 C3 时，用已授权的游戏界面查看账号、限时任务和进度。插件队列填「未读取」。[版本说明](https://github.com/RedeatI/cor3-relay/releases/tag/v2.2.1-relay)

## 接手时读一次

复用分给本线程的游戏标签，核对游戏显示的账号、插件实际版本和本号交接记录。C3 收起时也能读状态；需要明细再展开「任务」或「状态」。后台工具无法进入扩展弹窗时，可以直接使用游戏页上的 C3。仅有只读或后台权限时，沿用该限制。

支持读取页面 DOM 的工具可定位 `#cor3-helper-shell` 的开放 Shadow DOM，再定位 `#launcher`。一次读取下面这些公开界面属性即可；普通界面工具可读 C3 同名状态和按钮的无障碍标签。

| 要判断什么 | 读取什么 |
| --- | --- |
| 当前账号连接和队列是否可信 | `data-connection`、`data-queue-state`、`data-status-observed-at`。时间是本次本地采样时间；空值、已过时或 `unknown` 时复核当前页。 |
| 谁在占用端点 | `data-active`、`data-waiting`、`data-endpoint`、`data-blocked`。等待为 0 时仍可能有一项正在执行。 |
| 这一轮走到哪里 | `data-phase`、`data-processed`、`data-total`。已处理数含失败和跳过，结果见「任务 → 本轮明细」。 |

三个解密开关使用当前游戏页的连接。即使解密显示已连接，改配装、保存设置或派遣前仍要核实账号绑定和页面许可。遇到绑定变化、刷新或换号，丢弃旧页面的读数和控件引用。

## 什么时候等，什么时候动手

| 本号现场 | 线程下一步 |
| --- | --- |
| 单轮已排队、读取、等待小游戏、启动、等待确认、运行、核对结果或重连 | 跟进已有单轮，等阶段或已处理数变化后再读。期间保留游戏页，让插件完成自己的市场读取与提交。 |
| 有限时小游戏，或队列正被其他操作占用 | 先让正在执行的动作结束。有自然出现的小游戏，让本页已启用的解密功能接手；用游戏结果核实。单纯有一支远征在途中，可以继续不冲突的剧情。 |
| 自动跑市场已授权且已开启，任一市场到点 | 由 Relay 将缓存的刷新时刻与系统时间核对，读到新任务池后启动。关浏览器期间错过刷新，重开后补当前仍有效、尚未覆盖的池。单轮执行期间由线程观察进度，结束后交给 Relay 复核期间发生的刷新。 |
| 已获手动单轮授权，当前池待处理，账号许可正常、队列空闲且没有限时操作 | 在「任务」点一次「运行一轮市场任务」。看到排队或进度就跟进这次请求。沿用原任务类型和开关；单轮授权只覆盖这一次，不切换长期自动接单设置。 |
| 启动超时、`unconfirmed`、`blocked`、`lease-expired` 或队列未读取 | 记下时间和最近阶段，只读复核同一页的采样、日志、在跑委托和游戏反馈。送达未知时保留现场，不用再点启动、清锁、换窗口或刷新来试。有界等待后仍无新证据，记录未知结果、下一核验条件和负责人。 |
| 单轮已结束或取消 | 看成功、失败、跳过及错误明细。对领取、扣款等动作查本号游戏回执或余额、任务状态；确认队列和端点已空闲、没有限时界面，再继续主线、DAILY OPS 或远征。 |

线程被要求跟到结束时，等待当前页的阶段、计数或日志出现变化，再决定下一步。短时间进度不动时，先看最近日志和端点占用，保留上次读数，避免反复开面板或刷新四个市场。

例如 C3 显示「结束，4/4」，明细却是成功 0、失败 4：交接记「完成检查 4 项，成功 0 项」，保留失败原因。若端点同时显示市场读取，等这项读取结束再换装。

## 只补读缺的资料

配装和 Daily 的成功读数最多复用 5 分钟，雇佣兵远征和无人机为 1 分钟；市场最多 5 分钟，遇到本市场刷新时刻提前失效。页面首次连接会自动读取；快速重开 C3 继续使用近期读数。某一项缺失或刚有变更时只补读该项。缓存时间表示读取时间，领奖或换装仍以对应游戏结果为准。

保留本号原有预算和显式关闭项。升级后若设置显示「未读取」，先等绑定和读取恢复，再决定是否需要改动。远征配置及预算见[配装与远征](equipment-expeditions.md)。交接时把单轮结果、端点、游戏页是否保留和下次需要人工处理的事件写入[会话模板](../templates/session.md)。
