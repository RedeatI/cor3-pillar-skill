# 共享实战知识库

几个执行者或几条线程一起推号时，建一个本地共享库，专门存攻略没写全的路线、版本改动、试错失败记录和实测解法。各账号自己的余额进度留在本地进度文件里，通用踩坑经验进知识库，个人进度日志留在本地工作目录即可。

## 最小目录结构

```text
knowledge-root/
  README.md          入口、实际路径、维护者分工
  INDEX.md           编号、标题、状态、适用条件、关联条目
  AGENTS.md          维护约定
  TEMPLATE.md        从 skill 的 templates/problem.md 复制
  entries/           每个问题独立文件
```

给每个执行者分一个固定前缀（比如 A、B、SYS），条目按 `A-YYYYMMDD-001-主题.md` 命名。新建前先看最新编号防撞号，每人按问题单独开文件。首次建库时从 [问题模板](../templates/problem.md) 复制模板，并把下面几条规则写进库里的 `AGENTS.md`：

- 每轮开跑前先扫 `INDEX.md`，碰到卡点按关键词翻对应条目；每轮收尾把新坑、新解法或反例补进库里，确有新发现再建条目。
- 状态只用“已验证、部分验证、未解决、已失效”四种。把账号阶段、软硬件、触发条件、日期、尝试过程和界面实际反馈写清；还没查明的原因直接写未知。
- 改自己写的条目之前先重读一遍；要补充证明或推翻另一位作者的结论时，另建一篇关联条目，留着原来的证据。后续验证有了结果，顺手把当前结论改同步，旧观察标上日期留着，保持正文前后口径一致。
- 证据引用带日期的本地日志、截图或公开来源记录；记录“先后发生”时谨慎下因果结论，只拿正常推进顺便采到的样本，省得为凑条目额外花钱、重置或冒险重演。
- `INDEX.md` 如果库里已经配了自动生成脚本就用它；碰到并发锁忙等一会重试，让锁自行释放。没有生成脚本就定一个维护者合并索引，其他人只新建自己的条目文件并通知维护者，防止互相覆盖丢记录。
- 全库统一用 UTF-8。密码、验证码、Cookie、Token 或无关个人资料严禁进库；本机账号/profile 映射和原始截图留在非公开的本地会话目录里。

各线程只管各自获授权的账号，看过共享知识库里的经验后仍按本号授权边界走；只有用户授权跨线程协调时才彼此发消息。定时任务要读当前 skill、本账号进度和共享知识库入口，调度任务各自管好各自那份。

往 GitHub 公开分享前，只抽通用方法和必要游戏数据，把个人姓名/邮箱、线程 ID、profile ID、本机绝对路径、登录信息、兑换码和原始账户快照全部清干净。新实测先写进知识库，跑稳了再提炼进 skill。
