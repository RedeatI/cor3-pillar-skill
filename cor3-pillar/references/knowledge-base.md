# 共享实战知识库

为同一授权任务的多个执行者建立本地共享入口，保存攻略缺漏、版本差异、失败实验和解法。账号状态留在各自进度文件，可复用经验放知识库；不要把个人进度日志直接提交到公开技能仓库。

## 最小结构

```text
knowledge-root/
  README.md          入口、实际路径、维护者分工
  INDEX.md           编号、标题、状态、适用条件、关联条目
  AGENTS.md          维护约定
  TEMPLATE.md        从 skill 的 templates/problem.md 复制
  entries/           每个问题独立文件
```

每个执行者分配独立前缀，例如 A、B、SYS；文件名用 `A-YYYYMMDD-001-主题.md`。保存前检查编号，不共写一篇大日志。首次使用可从 [问题模板](../templates/problem.md) 建立条目，将这里的规则写入库内 AGENTS.md。

- 每轮开始先读索引，卡点按关键词查相关条目；每轮结束前补新问题、解法或反例，没有新知识不重复写。
- 状态使用“已验证、部分验证、未解决、已失效”。说明账号阶段、软硬件、触发条件、日期、尝试和实际反馈；未确定的原因明确写未知。
- 自己的条目修改前重读；对另一作者的结论补证或反驳时新建关联条目，保留原证据。后续验证完成后同步更新当前摘要，旧观察标注时间，不能同时写“已完成”和“仍在等待”。
- 证据引用带时间的本地日志、截图或来源记录；单次恢复不能推出普适修复，先后发生也不能证明唯一因果。不要为写条目额外购买、重置或冒险重演。
- 索引已有构建器就沿用；锁忙稍后重试，不盲删。没有构建器时指定一位维护者合并索引，其他执行者只写独立条目并通知维护者，避免覆盖丢记录。
- 文件用 UTF-8。库中不保存密码、验证码、Cookie、令牌或无关私人资料；本地账号/profile 映射与原始截图留在非公开会话资料。

共享知识不改变账号归属。跨聊天只在用户授权协调时发送；只读学习不代表获得另一账号的操作权。定时任务应读取当前 skill、本账号进度及共同知识库入口，调度仍由对应执行者维护。

发布到 GitHub 前只提炼通用方法和必要游戏数据，去除私人姓名/邮箱、线程 ID、profile ID、个人绝对路径、登录资料和原始账户快照。新实测先入库，稳定方法再修订 skill。
