# Agent Desktop 易错操作与验收

用于 Windows 上 COR3 窗口的观察、定位和操作排障。先读本机当前 Agent Desktop 与 Windows 平台说明，并按实际版本的帮助确认参数；这里不是另一套控制工具，也不扩展账号操作授权。用户要求保持后台时，不执行前台点击、焦点切换、全局键盘输入或改变用户正在使用的窗口。

## 已记录的 COR3 问题

- **渲染恢复和点击安全是两回事。** 2026-11-15 原执行线程记录 Agent Desktop 游戏点击此前曾抢前台；Chrome 恢复并获焦点后再次最小化，地址栏输入未送达。14:16 通过准确窗口句柄后台渲染实见 ForegroundUnchanged=true，并读到账号与余额，但当时没有证明 Agent Desktop 后续点击也不抢前台。不要用一次读取或窗口准备成功替代交互验证。
- **用户手动最小化不等于撤回授权。** 同日用户明确解释最小化是手动操作，并允许后台运行。应记录为当前后台执行能力问题，不写成用户拒绝；也不能据此恢复到前台强行点击。仅在已有授权且当前工具可保证后台条件时继续。
- **不要套用别号的接入配置。** 同一记录指出 BitFox 的 profile/接入方式不能直接用于普通 Chrome。动作前以当前窗口、浏览器及游戏可见账号核对目标；浏览器名字相同也不能证明是同一账号。
- **不要把旧坐标当作目标身份。** 2026-11-16 热图实测中，04 的视口不同，不能沿用05/07的像素坐标；缩放后才发现先前漏选的圆筒建筑。仅有红框或单次 Success 不等于地图已生成，需实见 Shot ready、Download、生成文件与实际发送状态。该结果验证的是画面定位与游戏验收，不是 Agent Desktop 坐标输入的后台能力。

来源：2026-11-15 14:16、14:24 的匿名执行交接（前一段记录输入未送达），以及 2026-11-16 热图实测。原始账号、窗口与线程资料不公开。历史观察不保证当前版本仍必然发生同一问题。

## 工具文档确认的执行规则，非本号修复实测

以下来自本机 Agent Desktop / Windows 说明；是否能解决当前 COR3 页面，仍须按本号现场验证。

### 窗口、最小化与空树

1. 先核对准确窗口及可见账号，不向同浏览器的其他标签或另一账号发送操作；出现用户输入冲突就停下当前动作并保留状态。
2. 最小化窗口可能使元素全部 offscreen；遮挡也可能影响 Chromium 初次构建可访问树。树小或空不等于游戏没启动。先检查窗口状态，再用有界等待和新的 snapshot；若边界节点有 children_count，则按需深入该区域，不能只无限增加等待。
3. 不为获取树而默认 focus-window、最大化、最小化别人的窗口或重新启动浏览器。当前不允许前台操作时，文档中需要前台的恢复办法不适用；记录精确阻碍，使用已有授权且符合限制的能力，不绕过访问拒绝。

### ref、重复控件与输入

- PowerShell 中把完整限定 ref 放在引号中，如 '@快照标识:e编号'；实际值只能来自当前工具输出，不能猜造。裸 @ 会被 PowerShell 当成特殊语法。
- UI变化后重新读取受影响区域。子区域重新 snapshot 后，其旧子 ref 可能失效；STALE_REF 或 SNAPSHOT_NOT_FOUND 时获取新的引用，不重复旧命令。
- Windows 的同名同身份控件可能返回 AMBIGUOUS_TARGET。缩小读取范围可帮助理解卡片，但不保证全窗口唯一性；重复点击同一 ref 或随意选第一个不能解除歧义。找真正唯一的控件与完整上下文。当前禁止前台操作时，不改用 headed 坐标输入解围。
- Windows 的 type 是实体键盘输入，press --app 也不是可靠的后台按进程投递。保持后台时只用实际支持的语义赋值；目标不支持则停止该动作，不能默默换成全局按键。赋值后核对完整可见文本、前导零、默认前缀及游戏是否真正提交，字段有文字不等于搜索或任务已生效。
- 只在另有明确前台操作许可时，才考虑当前截图对应的坐标路径；窗口移动、DPI、显示器、视口或缩放变化后重新观察，不复用旧像素位置。工具明确拒绝时不得换接口绕过。

### 送达、重试与最终验收

- 每个有副作用的操作执行一次，再读结果。分清 JSON 的 ok、disposition.delivery、disposition.retry 与游戏结果；工具返回成功不等于游戏已完成任务。
- 只有明确 not_delivered 且 retry:safe 才可安全重试同一动作。delivered_unverified、送达未知或 ACTION_FAILED 的 post_action_verification 都可能已发生操作，先读 post_state 和新画面，不能因报错重复输入、付款、接单或领取。
- delivered_verified 可能只验证控件值，application_commit 仍未验证。游戏内还须核实任务列表、余额、库存、对话或搜索结果。弹层出现后转向实际弹层；提交、确认和领奖分别验收。
- 异步页面使用有界状态等待；等待超时只说明本次未看到目标状态，不等于动作没送达。记录最后可见状态与是否存在未提交动作，再决定下一步。

文档依据：[Agent Desktop](https://agent-browser.dev/desktop) 与 [Windows 平台说明](https://agent-browser.dev/desktop/platforms/windows)，以及安装版本附带的 Chromium/Electron 与排障文档。参数与行为有版本差异，执行前读当前文档。未在本轮运行任何桌面动作来复现上述问题。
