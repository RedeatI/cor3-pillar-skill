# 黑市与市场 REP

适用于 ACT 3 的黑市 D4RK RM7MI，以及后续解锁的其他市场。黑市本身的市场声望是一条推进条件：剧情、账号名望或余额已经增长，并不能证明黑市商店的等级锁已满足。

## 先读对进度

分别记录账号 Renown、游戏累计收入、可用余额，以及 HOME、D4RK、SOYUZ、USOL 等已发现市场各自显示的 REP/CRL。保留界面的等级和 XP 分子/分母，不把奖励里的 REP 点数当成整数级，也不把不同市场的数值相加。没有打开或无法访问的市场写明原因，不能默认是 0 级或任务清空。

为每个受阻目标写出依赖，例如“缺兼容 eb54x 的解密软件 → 当前商店要求 D4RK 3 级 → 先完成 D4RK 委托”。区分缺钱、缺等级、缺软件格式支持、入侵强度不足；有钱时仍可能买不了，买到软件也仍须核对配装和支持类型。

## 黑市还没出现

先查本账号已有 E1SCP 文件、地图搜索结果和相邻节点状态。社区入口线索是读取 `sw12_sec_report_2341245.txt`，再在游戏 Network Map 搜索虚构 IP `855.528.0.4`，寻找 D4RK RM7MI；失败时检查 E1L5/E1SCP 维护与路线。此路线来自 [社区攻略 ACT 3](https://wiki.mistarg.cn/index.php/COR3)，2026-11-09 查阅，须在当前账号验证。不能对该虚构 IP 发起真实网络请求。

区分能否连接服务器、能否进入 Market、能否访问受保护的文件。不要把文件登录所需权限直接推断成整个市场不可用。一次搜索无结果时记录具体反馈，再查前置和路径，不反复输入相同内容。

## 已出现但 REP 不够

1. 从目标市场进入 Jobs，读该市场当前 REP、任务奖励、保证金、期限、失败惩罚及访问条件。把能解除当前剧情或工具瓶颈的市场委托列入本轮，不能只按 CR 奖励选择 HOME。
2. 沿用用户的未知任务策略和预算：预留已承诺支出，区分未知与已确认不可完成。提高 REP 也不能成为反复接同一已知失败项的理由。
3. 接取 → 完成指定操作 → 回到发单市场提交 → 等待任务状态、奖励和该市场 REP 更新。下载文件、解谜完成或显示“可完成”都不等于结算；读数未变时先核实提交和刷新，不能靠重复点领奖补数。
4. 每次跨过等级门槛，重新查相关商店的商品、价格、软件支持类型、授权和新任务，再回到受阻剧情/地图验证。不要假定 REP 升级必然自动完成剧情，也不要为确认解锁而随意购买。
5. 本市场暂无任务时，记录实际刷新倒计时；继续其他可执行市场、日常和剧情。下一轮合并有效时点，保留已接任务期限。不要用 HOME 的倒计时推算 D4RK，也不要固定每几分钟查看空列表。

## 可追溯的门槛与限制

2026-11-09 本项目历史实测：一个 Foundation 样本账号 Renown 11.537、余额 44,375 CR，但 D4RK 为 2.064 级（161/2500）。商店的 5CRYPt0L 09 当时售价 42,250 CR、要求市场 3 级，资金已够仍不能购买。之后完成并结算三项 D4RK 委托，市场达到 2.229 级（572/2500）；相应软件仍未解锁。这证明需要单独推进市场 REP，不证明其他任务都会给予相同 XP。

社区资料另记载 D4RK REP 4 的 H0pp3r、REP 5 的部分硬件购买门槛；REP 3 的特殊服务器委托说法仍有不确定性。完成 ACT 2 Stage 9 的账号也可检查 Silver Odyssey 中的免费 5CRYPT0L 线索。以上均须核对当前界面和账号资格，不把跳过早期剧情的账号默认视为已有奖励。[来源](https://wiki.mistarg.cn/index.php/COR3)

当前市场等级、下一项实际需要的解锁、所缺 XP、可做委托、具体阻碍和刷新时间，写入 [会话记录](../templates/session.md)。这项检查不能只做首次：任务失败、解锁新市场或目标改变后都要重读。
