# 收尾、总览与续办

仅在本轮实际执行结束时读取；维护 skill 不启动账号，也不修改调度。

## 收尾与下一轮

1. 将真实结果写入本账号进度和原账号总览：已提交/领取项目、余额与收入口径、当前配置、进行中任务/押金/期限、Echoes 的 A/B 与 C 各支进度、已解锁与已发现的碎片数、市场访问与 REP、远征 Reliability（当前值、最后实读时间、来源面板）、专家解锁核查（原始要求、对应指标是否已确认、实际可用状态）、远征在途/尾款/待领取状态、各自阻碍与下一步。总览使用用户已有的更新方式，将 Reliability 单独列示；缺失或未实读记“未核实”，不填0、不沿用 Renown/市场 REP，不把旧值当实时值。未确认专家门槛所指指标时，差额也记“未核实”。未核实项注明。不能将待验证、待领奖写成完成。
2. 新问题、解法或反例按知识库模板单独写条目，注明账号条件、日期、尝试、结果、限制和证据。遵守共享库的作者分工；更正他人结论另建关联条目。补充后更新当前结论，避免正文“仍未完成”与后续验证相互冲突；保留带日期的旧观察。
3. 新增或更新条目后，按 [知识库约定](knowledge-base.md) 使用本地已有索引生成器；无新知识不制造重复记录，索引锁忙时稍后重试，不盲删锁。
4. 关闭或卸载本轮授权账号的 COR3 游戏页，保留浏览器、其他标签及登录。后台模式按接入文档清理并验证；用户正在前台使用时不抢占窗口。异常退出也尽力完成这一收尾，未验证成功则明确说明。
5. 确有后续工作时，按真实刷新、维护结束、任务期限或远征结果安排下一次单次运行。用户要求减少频率时，合并临近有效时点，不为无变化状态或短暂远征选择每几分钟唤醒；已接任务期限与到期风险仍需记录。未知时间说明依据，不能编造精确倒计时。
6. 只有用户授权且平台支持时才安排续办。Codex 使用 `automation_update`，其他宿主使用其支持的调度工具，更新本线程已有任务；先读最新完整字段，保留目标线程、名称和通知偏好。提示词只写 skill 路径、负责账号和仍有效的特殊待办，常规流程读 skill，历史状态留在交接。避免覆盖另一个执行者的新安排。维护 skill 本身不改变游戏日程。核对用户时区与调度时区、仅一次且在未来、UTF-8 中文与路径正常，重读验证。不用原始 TOML 写入，不新建重复任务。
7. 已验证达到 The Pillar 后停止该账号自动推进并报告。若一个自动任务管理多个账号，只移除已达标账号的后续操作，其余继续；全部负责账号达标后再暂停该任务。其他情况简述本轮进展、具体阻碍、下一时间和网页收尾结果。
