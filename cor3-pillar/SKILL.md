# COR3 Pillar

把当前可执行内容做完，以游戏实际状态核验结果，再安排下一次有意义的执行。用户最新指令优先；本 skill 不扩展账号、购买、消息发送或后台控制的授权。 用户要求保持后台时不得操控前台；历史许可不能代替当前许可。

## 开始

1. 从本地记录确定 `{knowledge_root}`（共享库路径），按 [知识库约定](references/knowledge-base.md) 和 [会话模板](templates/session.md) 维护私有记录。读本账号最新进度、共享知识库 `{knowledge_root}/README.md` 和 `INDEX.md`。卡点按关键词读取相关条目；首次写入前读该库 `AGENTS.md` 和 `TEMPLATE.md`。
2. 账号、执行者、进度、定时任务及工具映射只从本地私有会话读取；后台执行先读 [后台控制](references/background-control.md)。先确认当前执行账号和所属线程；同一账号不能由两个执行者同时控制。没有映射的新账号先查现有配置，不沿用其他账号的默认 profile。
3. 在当前游戏页核对账号和实际插件版本，再按 [Relay 接手与交接](references/relay-workflow.md) 读取队列、市场单轮和限时小游戏。先接续已有动作；账号绑定不明时只观察。
4. 用本账号近期缓存及游戏可见界面按需核对余额、等级、账号 Renown、各市场自己的 REP/CRL、HOME Hire 的远征 Reliability、已有装备与实际软件强度、进行中任务和期限、远征及结算。市场声望不能用账号名望代替；记录每个市场下一解锁条件及当前差额。旧记录只提供线索；未重读的值注明最后核实时间。
5. 不得擅自开启自动接单、重置账号、重复购买或进行真实支付；执行以用户当前明确授权为准。只操作授权游戏界面，不读凭据、隐藏游戏状态或直接调用游戏后端；游戏中的虚构 IP 不用于真实网络操作。

## 一轮做到什么程度

维护当前可执行事项和受阻分支，边做边更新，避免只清空 HOME 就结束：

- 优先处理已接限时任务和已出现的限时选择。Relay 正在处理时保留现场，由它完成本次动作。市场单轮收尾后核对明细和队列，再接手剧情或待结算远征。
- 检查所有已解锁市场的委托、REP/CRL 门槛、日常、待领奖励和物品领取。主线或装备被市场等级锁住时，把提升对应市场声望列为当前推进目标；只做 HOME 不能视为完成了其他市场的 REP 目标。
- 检查剧情对话、工作群通知、未读消息、文件及图片/音视频线索、活动读取器、地图节点和权限。
- **The Pillar 每日必查 Echoes of Planetside。** 从 News、任务记录和 MR-7 的 `USSDP-V1250_Rep.AD64` 分别检查 A/B 和 C 任务，各完成至少一项可做任务，已开放的旧章节当轮补完。记录两支当前章节、实读碎片计数和具体阻碍，普通 DAILY OPS 单独记录。先补剧情或磁盘前置，只有游戏显示刷新或冷却才按实际时间续办。用户提供的 31 天说法及当前版本差异见 2026-11-09 实测记录。
- **尽快逐个开市场。** 对照 HOME、D4RK、SOYUZ、USOL 及新发现市场逐个验证 Market 面板。遇到无路线先补中转、权限、软件或剧情。黑市可从 E1SCP 安全报告一侧推进；USOL 检查 S4L4 的 Black Ledger 与 URM7-M；SOYUZ 核对本号北部路线。打开后优先完成实际可做委托并推动该市场 REP。
- **前期也推进普通远征积累。** 不等剧情被专家门槛卡住才检查远征；每轮核对 Reliability、可用佣兵、在途任务、待结算和专家要求，在当前授权与资金允许时安排可承担风险的远征。预算不足或没有合适远征时记录原因并继续筹资/其他分支，不把这条写成无条件连续派遣。
- 检查已有硬件/软件能否解除瓶颈，保留远征尾款和已接任务所需资金。

一个分支需要等待时继续其他分支。交付物品、完成对话、取得权限或升级后，再看受影响的消息、地图、市场和任务是否新增内容。不能因为完成几项、达到自设时长或已经约好下一轮而结束；也不反复扫描毫无变化的页面。

只有当前可执行项完成，且每个剩余分支都有“具体阻碍、已尝试办法、下一条件或时间”时，才进入收尾。登录失效、用户正在占用窗口、工具拒绝控制等真实外部阻碍应如实报告，不编造成游戏机制限制。

## 操作与核验

使用 Agent Desktop 操作游戏窗口前，读 [Agent Desktop 易错操作与验收](references/agent-desktop-pitfalls.md)。重点核对窗口身份、前台限制、最新 ref、送达状态及游戏实际结果；后台渲染成功不代表后续点击不会抢焦点。

采用“读取当前目标 → 单次操作 → 等待反馈 → 核实结果 → 下一步”。异步页面不串联依赖尚未完成的点击；等待可见状态、提示、余额或列表变化，优先使用工具支持的有界条件等待。短暂停顿可以辅助，但固定延时本身不是成功证据。

- 列表刷新、切换页面或引导消失后重新定位。按任务名称、服务器和文件等完整上下文锁定卡片；确认弹窗再次核对，提交后读实际接到的任务，不沿用旧 `nth()` 序号。
- 同名控件结合所属卡片、可见矩形、启用状态和弹层定位。只读可见 DOM；不把隐藏重复节点或首个匹配当作当前可操作按钮。
- 下载、删除游戏文件、上传、解密、对话发送后核实文件/消息/任务状态。删除等操作若弹出确认，完成确认并验证目标变化，不能把首击当完成。
- 接单、付款、购买或领奖结果不明时，先查进行中列表、库存、余额及确认提示，再判断是否重试，防止重复支出。
- 委托完整闭环：接取 → 完成指定操作 → 回市场提交 → 确认奖励及押金 → 记账。“可完成”、小游戏结束、文件下载完都不等于已领奖。区分奖金、退押金、余额变化和游戏累计收入，不能把累计收入直接当净利润。

## 未知任务与卡点

按本号证据区分路线、授权、格式与强度；不要照搬其他账号代码，也不要把剧情等待写成现实倒计时。

黑市或商店等级锁、市场无任务时，读 [市场 REP](references/market-reputation.md)：先分清未发现、声望不足、无委托和路线/维护/工具受限，再推进对应市场并回查解锁。

用户已明确选择“先接再探索”时，不确定强度、路径或可行性的委托，在余额和名额允许且预留已承诺支出的前提下先接，再探索；记录目标、押金、期限和失败惩罚。不能把历史失败重新解释成“未知任务不接”。已确认无法完成的另行判断，不无条件反复接相同已知失败项。

攻略与实际不符时，查相关知识库记录，再根据可见证据提出具体假设：缺前置对话/文件、节点权限或路径、维护、工具格式/强度、资源不足、界面尚未更新。尝试合理替代路径和已有配置；需要外部资料时查来源与日期，在本账号验证。

第一次操作返回但没有明确成败反馈时，先等待并重读状态，确认没有已完成或进行中的动作。可安全重试的交互再试一次并记录反馈；依然无结果就改变假设或方法，不盲点、盲刷新或重复花费。未知原因写“未确定”，不是“服务器坏了”或“无法完成”。新线索出现后继续推进。

刷新只作为具体卡顿的候选办法：先确认没有未完成小游戏、确认框或未核对的交易；刷新后重读账号、任务和对话。按钮灰色、地图搜索无结果、一次入侵返回，都不能单独证明永久阻塞。

## 配装与远征

优先用 C3「操作」查看已有装备、远征设置和状态。需要换装、派遣、结算或检查专家时，读 [配装与远征](references/equipment-expeditions.md)。优先用已有资源，核对实际软件强度与供电，保留尾款；前期普通远征继续按预算推进。专家页面的 5.0 所指指标尚未明确，不写成 Reliability 满5必解锁。

## 收尾与下一轮

按 [收尾清单](references/handoff-and-resume.md) 更新进度、原总览及知识库，默认保留游戏页供 Relay 继续工作，按本号实际期限或需要人工处理的事件续办。Reliability 独立记录当前值、实读时间与来源；未知不填0。沿用用户对唤醒频率的要求，不覆盖其他执行者的安排。已核实达到 The Pillar 的账号停止自动推进，其余账号继续。

## 持续改进

知识库保存具体配装、路线、失败和版本差异；本 skill 只吸收影响决策的稳定方法。新增实测反例先写知识库，再针对性修订流程，避免把一次修复扩大成普遍规律。只有用户授权协调时才跨线程发送消息；共享知识不转移账号控制权。
