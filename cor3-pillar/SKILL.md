# COR3 Pillar

把这一轮能点的活都做完，盯着游戏界面确认到账和状态变化，有真实冷却或刷新时间再约下一轮。用户最新指令优先；账号范围、花钱预算、发消息和后台接管都严格按已有授权走。

`{knowledge_root}` 指本地共享实战库的实际目录，按实际路径填入。先从本地会话或项目记录里找已有库，多个执行者共用同一个；还没建库且需要持续跟号时，按 [知识库约定](references/knowledge-base.md) 和 [会话模板](templates/session.md) 建立本地记录。仅做维护 skill、研究或复盘时，保持游戏账号不动。

## 工具分工

- **浏览器控制**：读界面、走 Network Map、接交委托、看对话和确认结果，优先用当前环境已授权的接口。
- **COR3 Helper**：只开用户允许的固定解谜开关（如 `Auto Decrypt Hacking`、`Auto ICE Wall Hacking`、`Auto Simple Decrypt Hacking`），其余保持关闭；对照 [项目说明](https://github.com/Femtoce11/cor3-helper) 和实际界面使用，插件跑着的时候先等它走完，别同时去点同一块谜题。开关显示 ON 后以游戏内谜题过关为实，汇报时把“插件项目声称支持”和“这次实测结果”分开写。
- **agent-desktop**：只有确需点浏览器工具栏、扩展弹窗或原生窗口时才用来补位，用前先读已装技能及对应平台文档。语义操作仍可能触发焦点变化，用到前台键鼠时也要如实标为前台操作；遇到工具安全策略拒绝时直接停下报错，禁止换接口绕过。

## 开跑前先核对

1. 读本账号最新进度、共享库 `{knowledge_root}\README.md` 和 `INDEX.md`。遇到卡点按关键词翻相关条目；首次往库里写内容前，先读该库 `AGENTS.md` 和 `TEMPLATE.md`。
2. 从本地会话记录读出账号代称、负责线程、浏览器/profile、进度文件、可用工具和现有定时任务。一个账号同一时间只交给一个执行者操作；新账号先查各自真实配置，从头对齐对应的 profile。需要后台跑时，先读 [后台控制](references/background-control.md)。
3. 在游戏可见界面重读一遍数据：等级、账号 `Renown`、游戏累计收入、可用余额、各市场各自显示的 `REP/CRL`（含等级和 XP 分子/分母，市场 REP 与账号 Renown 分开算）、当前硬件与实际软件 `Power`、在跑委托与期限、远征及待结算状态、每个市场距离下一解锁还差多少。旧记录只作线索，未在界面重读的数字注明最后核实时间。
4. 对照游戏当前 `The Pillar` 条件和用户约束，一切门槛和优惠以眼前界面为准。用户已给的预算、插件开关、未知任务策略和授权持续有效，直接沿用即可。只操作授权的游戏界面，买前查重，虚构 IP 仅作站内节点用；未经授权严禁开启 `Auto Job`、自动卖物、账号重置或真实支付，禁止读取登录凭据、隐藏游戏状态、直调游戏后端或对虚构 IP 发起真实网络请求。

## 一轮要跑哪些线

按这个范围和顺序跑，把能推的线一次带通：

1. **快到期和待收尾的先做**：已接的限时委托、待结算/待领物品的远征、已经弹出的限时剧情选择。
2. **挨个检查市场（HOME、D4RK、SOYUZ、USOL 及新出现市场）**：先打通能解的路线、权限或剧情前置；**能打开 Market 并看到 Jobs 列表，才记为已开**（只连上节点或地图亮出图标还不够）。所有已开市场都要看一遍 Jobs、REP/CRL 门槛、待领奖励和待领物品；主线或关键软件被某市场等级锁住时，把刷这个市场的 REP 列为本轮优先目标——清完 HOME 后还要继续盯住目标市场。做法见 [黑市与市场 REP](references/market-reputation.md)。
3. **每天双线查 Echoes**：每天逐号检查 [Echoes of Planetside](references/echoes.md)。A/B 和 C 两支每天各完成至少 1 项可做任务，已经开放的旧章节当轮补完；分别记录两支的完成进度和卡点，只有游戏明确显示冷却或刷新时间才据此续办。Game Center 里的普通 `DAILY OPS` 另开一行记。
4. **剧情与线索**：看 Messenger 对话、工作群通知、未读 Mail、刚下载的文件和图片/音视频线索、MR-7 活动读取器、Network Map 节点与权限。
5. **卡强度先查现成配装**：先看已有的硬件/软件能不能调出够用的 Power，留够远征尾款和已接委托所需资金后再考虑买新件。

一条线在等冷却或远征时，立刻切去做另一条线；交完物品、打完对话、拿到权限或升了 REP 之后，回头扫一遍受影响的对话、地图、商店和 Jobs 列表有没有出新项。只要还有可推进的分支就接着往下跑，手头的线确实没新动静时再切换，省得在无变化的页面干耗。

手里能做的活都清完，且每条剩下的分支都写得出“具体卡在什么、试过什么、等哪个条件或几点刷新”，再进入收尾。遇到登录失效、用户自己在用窗口或工具拒绝控制这类外部情况时如实写出来，写明真实阻碍而不是归进游戏限制。

## 点击、找卡与交付验收

- **点一下看一次结果**：页面异步刷新，上一动还没回响前先等一拍，别连点；等游戏提示、余额变动、列表刷新或目标控件出现再走下一步，优先用工具有界条件等待，以界面真实变化为准。
- **刷新后按上下文重找卡片**：列表刷新、切页面或引导消失后，按任务名称、服务器和文件重新锁定卡片；点确认弹窗前再核对一遍，接单后回看在跑列表确认接对单，跳过旧的 `nth()` 序号。
- **只点可见可点控件**：遇到同名按钮，结合所属卡片、可见区域、启用状态和当前弹层定位；只从可见 DOM 里点亮着、能点到的那个目标按钮（跳过隐藏节点，也别顺手点页面第一个同名按钮）。
- **动文件、发消息、删东西后必复查**：下载、删除游戏文件、上传、解密、发对话后回查文件/消息/任务状态。删除等操作若弹确认框，点完确认并看到目标真变了才算完。
- **花钱和领奖不明先查账**：接单、付款、购买或领奖没看清结果时，先看在跑列表、库存、余额和确认提示再决定后续动作，防止重复支出。
- **委托跑全套再记账**：接单 → 按要求做完 → 回发单市场提交 → 看清奖金、退回押金和余额变化 → 再记账。只有奖金和退押金真正落账才算领过奖（卡片显示 `READY TO COMPLETE`、小游戏打完、文件下载完都只是前置步骤）；奖金、退押金、钱包余额和游戏累计收入分开记，净赚按实收余额差额算。
- **常见界面怪象先对实测**：遇到图纸已读无新对话、远征合同付款灰按钮、可结算委托点不开、已购配件换不上，先按 [实测摘要](references/field-notes.md) 查面板遮挡、条款勾选和前置步骤，再决定重试、等待还是记卡点。

## 未知任务与卡点排查

- **黑市与等级锁**：进 ACT 3、发现黑市 D4RK RM7MI、遇到商店等级锁或剧情没新回复时，读 [黑市与市场 REP](references/market-reputation.md)。先分清“市场未发现”“市场 REP 不够”“Jobs 暂无新单”“路线/维护/工具受限”；缺 REP 时直接去刷对应市场 Jobs 并交单核对 REP，跨过门槛后重查商店、授权、地图与相关对话，免得对着剧情干等。
- **未知任务策略**：按用户定下的策略执行。用户已经明确要求“先接再探索”时，只要余额和接单名额够、并留足已承诺支出，就算还摸不清所需 Power、路线或过关把握也先接下来，记清目标、押金、期限和失败惩罚；把历史失利当作参考线索，每个号按各自用户的风险授权独立判断。只有当前号测死确认做不了的同类单，才跳过反复接单。
- **攻略与实际不符**：先查相关知识库条目，再对照可见界面列出具体排查方向——缺前置对话/文件、缺节点权限或路径、节点维护、软件格式或 Power 不够、资源不足、界面没更新。试可行的替代路线和现成配置；查外部攻略时记清来源和日期，并在本号实测。
- **点完没反馈 & 何时刷新**：第一次操作返回但没看到明确提示，先等并重读状态确认动作到底在不在跑；确认安全且不会重复扣费的交互最多再试一次并记反馈，仍无果就换假设或路线。查不出原因写“未确定”，出现新线索继续推进。按钮灰、Map 搜不到、入侵失败一次都先当待排查线索；只有确认没有正在跑的小游戏、确认框或未对账交易时才用刷新，刷完重读账号、任务和对话。

## 配装与远征

- **配装**：先看目标软件的 CPU/GPU/RAM 需求、分配和黄色提示，再看主机电源余量、已拥有部件和并装软件抢资源情况。先拿手里已有件做可逆调整；确需购买时按真正卡脖子的部件、预算和配套供电挑选（更贵的 CPU 未必拉高目标软件 Power）。换装前记下原配置，关闭游戏内服务器并以“系统已关闭”通知确认（电源状态以通知为准，忽略静态 `POWER ON` 标题），再装/换件、开机，重读实际软件 `Power` 并对目标防御或加密文件实测。同一轮同时改动 GPU 和电源只记作“该组合有效”，换号仍要重新实测。案例对照见 [实测摘要](references/field-notes.md)。
- **远征**：分别核对报价、预付款、尾款和界面佣金描述。付款后看清余额扣款和远征状态；返回后结算、从信箱领回物品并确认进了库存，再推进剧情对话。总实付以实际扣款之和为准（界面佣金已含在总价口径内）。远征等待期间切去推别的分支。

## 收尾与约下一轮

1. **写明真实账面**：把结果写进本账号进度——已交单/领奖项目、余额与游戏累计收入、当前配置、在跑任务/押金/期限、每个阻碍与下一步条件。停在“可完成”或待验证的项目按实标为待结算/待核对。
2. **有新发现再记知识库**：确有新问题、解法或反例时，按 [知识库约定](references/knowledge-base.md) 和 [问题模板](templates/problem.md) 另建条目写透，标清作者前缀、账号条件、日期、尝试、结果、限制和证据。更正他人结论另开关联条目；后续验证完成后同步更新当前结论并给旧观察标上日期，保持正文前后一致。索引更新按库里现有生成器和并发锁规则走。
3. **清理游戏标签页**：关掉或卸载本轮操作这个号的 COR3 游戏页，保留浏览器、其他标签和登录状态；后台模式按接入方式收尾并复查没遗留游戏页，遇到用户正在前台用窗口就保持原样。异常退出也尽力完成这一步，未验证关掉时在报告里直说。
4. **约下一次单次运行**：只有用户授权定时执行且平台支持时才安排。确有后续工作时，按真实刷新、维护结束、任务期限或远征返回时间约下一次**单次**运行；用户要求降频时把临近有效时点合并成一轮（仅在确有时间变化时唤醒），同时记清在跑任务期限，并说明合并检查对短暂选择的影响。估算时间写明依据，严格以游戏真实显示的倒计时或规律为准。
5. **调度更新要求**：Codex 中用 `automation_update` 更新本线程已有任务；其他宿主用各自支持的调度接口，没有接口就说明未安排。更新前先读最新完整字段，原样保留目标线程、名称、提示、通知偏好等，以免覆盖别的执行者刚改的安排（仅修改 skill 文档时保持现有游戏日程不变）。改调度时核对用户时区和调度时区（如 UTC）、确认仅一次且在未来、UTF-8 中文与路径正常，改完重读验证；严禁直接写原始 TOML 或新建重复任务。
6. **达标停更**：界面验证达到 `The Pillar` 后，停掉该账号的自动推进并汇报。如果一个自动任务管理多个号，只把已达标账号移出后续计划，其余照跑；全部负责账号都达标再暂停这个任务。其余情况简报本轮进展、具体阻碍、下一运行时间和网页收尾结果。

## 经验沉淀与协作边界

知识库留存具体配装、路线、失败记录和版本差异；本 skill 只吸收会影响操作顺序和判断标准的稳定规则。新增实测反例先写进知识库，多号跑稳了再修订 skill，单次偶然修复只留作个案。跨线程发消息仅在用户授权协调时使用，共享知识与账号操作权彼此独立。
