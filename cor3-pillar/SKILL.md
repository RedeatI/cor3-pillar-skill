# COR3 Pillar

把当前可执行内容做完，以游戏实际状态核验结果，再安排下一次有意义的执行。用户最新指令优先；本 skill 不扩展账号、购买、消息发送或后台控制的授权。

`{knowledge_root}` 指本地共享实战库的实际路径，不是要照抄的目录名。先从会话/项目记录发现已有库，多个执行者使用同一入口；没有库且任务需要持续记录时，按 [知识库约定](references/knowledge-base.md) 和 [会话模板](templates/session.md) 建立本地记录。维护技能、研究或复盘不启动游戏操作。

## 工具分工

- 浏览器控制负责读取当前任务、判断路线、操作和核验，优先用当前已授权的接口。
- COR3 Helper 仅辅助用户允许的固定解谜；按其 [项目说明](https://github.com/Femtoce11/cor3-helper) 和实际界面选择 Auto Decrypt Hacking、Auto ICE Wall Hacking、Auto Simple Decrypt Hacking 等所需开关，不默认全开。插件工作时不要同时点击同一谜题，开关 ON 不等于成功；记录“项目声称支持”与本次实测的差别。
- agent-desktop 只在确有工具栏、扩展面板或原生窗口操作需求时补位，先读已安装的技能及平台文档。语义动作不保证后台无焦点影响，前台键鼠也不能冒充后台操作。工具安全拒绝时不换接口绕过。

## 开始

1. 读本账号最新进度、共享知识库 `{knowledge_root}\README.md` 和 `INDEX.md`。卡点按关键词读取相关条目；首次写入前读该库 `AGENTS.md` 和 `TEMPLATE.md`。
2. 从本地会话记录读取账号代称、负责线程、浏览器/profile、进度文件、工具与已有自动任务映射。同一账号不能由两个执行者同时控制；新账号先查实际配置，不沿用另一账号的默认 profile。需要后台操作时读 [后台控制](references/background-control.md)。
3. 游戏可见界面核对余额、等级、账号 Renown、各市场自己的 REP/CRL、已有装备与实际软件强度、进行中任务和期限、远征及结算。市场声望不能用账号名望代替；记录每个市场下一解锁条件及当前差额。旧记录只提供线索；未重读的值注明最后核实时间。
4. 读取游戏当前 The Pillar 条件与用户约束，不把历史门槛或优惠写成现行事实。已有预算、插件开关、未知任务策略和操作授权持续有效；不要因加载 skill 重问。未经授权不启用 Auto Job、自动卖物品、重置或真实支付；避免重复购买。只操作授权游戏界面，不读凭据、隐藏游戏状态或直接调用游戏后端；游戏中的虚构 IP 不用于真实网络操作。

## 一轮做到什么程度

维护当前可执行事项和受阻分支，边做边更新，避免只清空 HOME 就结束：

- 优先处理已接限时任务、待结算远征和已出现的限时选择。
- 检查所有已解锁市场的委托、REP/CRL 门槛、日常、待领奖励和物品领取。主线或装备被市场等级锁住时，把提升对应市场声望列为当前推进目标；只做 HOME 不能视为完成了其他市场的 REP 目标。
- 逐个核对 HOME、D4RK、SOYUZ、USOL 及游戏新显示的市场。能解除的路径、权限或剧情前置当轮处理，以实际打开 Market 面板确认开放。参见 [市场解锁与 REP](references/market-reputation.md)。
- 每天逐号检查 [Echoes of Planetside](references/echoes.md)。A/B 和 C 两支各完成至少一项可做任务，已开放的旧章节当轮补完。分别记录两支的完成进度和阻碍，只有游戏明确显示冷却或刷新时间才据此续办。普通 DAILY OPS 另记。
- 检查剧情对话、工作群通知、未读消息、文件及图片/音视频线索、活动读取器、地图节点和权限。
- 检查已有硬件/软件能否解除瓶颈，保留远征尾款和已接任务所需资金。

一个分支需要等待时继续其他分支。交付物品、完成对话、取得权限或升级后，再看受影响的消息、地图、市场和任务是否新增内容。不能因为完成几项、达到自设时长或已经约好下一轮而结束；也不反复扫描毫无变化的页面。

只有当前可执行项完成，且每个剩余分支都有“具体阻碍、已尝试办法、下一条件或时间”时，才进入收尾。登录失效、用户正在占用窗口、工具拒绝控制等真实外部阻碍应如实报告，不编造成游戏机制限制。

## 操作与核验

采用“读取当前目标 → 单次操作 → 等待反馈 → 核实结果 → 下一步”。异步页面不串联依赖尚未完成的点击；等待可见状态、提示、余额或列表变化，优先使用工具支持的有界条件等待。短暂停顿可以辅助，但固定延时本身不是成功证据。

- 列表刷新、切换页面或引导消失后重新定位。按任务名称、服务器和文件等完整上下文锁定卡片；确认弹窗再次核对，提交后读实际接到的任务，不沿用旧 `nth()` 序号。
- 同名控件结合所属卡片、可见矩形、启用状态和弹层定位。只读可见 DOM；不把隐藏重复节点或首个匹配当作当前可操作按钮。
- 下载、删除游戏文件、上传、解密、对话发送后核实文件/消息/任务状态。删除等操作若弹出确认，完成确认并验证目标变化，不能把首击当完成。
- 接单、付款、购买或领奖结果不明时，先查进行中列表、库存、余额及确认提示，再判断是否重试，防止重复支出。
- 委托完整闭环：接取 → 完成指定操作 → 回市场提交 → 确认奖励及押金 → 记账。“可完成”、小游戏结束、文件下载完都不等于已领奖。区分奖金、退押金、余额变化和游戏累计收入，不能把累计收入直接当净利润。
- 遇到图纸已读无新对话、合同按钮灰色、可结算卡片打不开或已购配件换不上，先按 [实测经验](references/field-notes.md) 核对界面前置，再决定重试、等待或记录阻碍。

## 未知任务与卡点

进入 ACT 3、发现黑市 D4RK RM7MI，或遇到商店等级锁、剧情无新回复时，读 [黑市与市场 REP](references/market-reputation.md)。先区分“市场未发现”“市场声望不足”“无新委托”“路线/维护/工具受限”，不能只循环点剧情或把缺 REP 写成只能等待剧情更新。提升 REP 需要在对应市场完成委托并提交结算；达到门槛后重新检查商店、授权、地图与相关对话。

沿用用户选择的未知任务策略。用户已明确要求“先接再探索”时，不确定强度、路径或可行性不能作为拒接理由；在余额和名额允许且预留已承诺支出的前提下接取，记录目标、押金、期限和失败惩罚。不能把历史失败重新解释成拒接要求，也不把某位用户的风险偏好默认为所有用户授权。已确认无法完成的另行判断，不无条件反复接相同已知失败项。

攻略与实际不符时，查相关知识库记录，再根据可见证据提出具体假设：缺前置对话/文件、节点权限或路径、维护、工具格式/强度、资源不足、界面尚未更新。尝试合理替代路径和已有配置；需要外部资料时查来源与日期，在本账号验证。

第一次操作返回但没有明确成败反馈时，先等待并重读状态，确认没有已完成或进行中的动作。可安全重试的交互再试一次并记录反馈；依然无结果就改变假设或方法，不盲点、盲刷新或重复花费。未知原因写“未确定”，不是“服务器坏了”或“无法完成”。新线索出现后继续推进。

刷新只作为具体卡顿的候选办法：先确认没有未完成小游戏、确认框或未核对的交易；刷新后重读账号、任务和对话。按钮灰色、地图搜索无结果、一次入侵返回，都不能单独证明永久阻塞。

## 配装与远征

硬件决策先看目标软件的 CPU/GPU/内存等资源需求、分配与黄色提示，以及主机电源余量；检查已拥有部件和并装软件争用。先用已有资源做可逆调整，确需购买时结合实际瓶颈、预算及配套供电，不按“更贵 CPU 就更强”推测。

切换时记录原配置，关闭游戏内服务器，以通知确认关机，再安装/更换并启动。读实际软件 Power，并对目标防御或文件强度验证。静态 `POWER ON` 标题不能判断开关状态。同时改动 GPU 和电源，只能证明该组合有效，不能单独归因；其他账号必须复核。具体对照见 [实测经验](references/field-notes.md)。

远征分别核对报价、预付款、尾款及佣金描述。支付后确认余额变化与远征状态；成功返回后结算、领取物品并检查库存，再推进对话。总实付按实际扣款相加，不能把界面佣金再推算成已扣金额。远征等待期间继续其他可行分支。

## 收尾与下一轮

1. 将真实结果写入本账号进度：已提交/领取项目、余额与收入口径、当前配置、进行中任务/押金/期限、每个阻碍与下一步。不能将待验证、待领奖写成完成。
2. 新问题、解法或反例按知识库模板单独写条目，注明账号条件、日期、尝试、结果、限制和证据。使用会话中分配的作者前缀；更正他人结论另建关联条目。补充后更新当前结论，避免正文“仍未完成”与后续验证相互冲突；保留带日期的旧观察。
3. 新增或更新条目后更新知识库索引。已有生成器时沿用并检查结果、编码和并发锁；没有生成器时由单一维护者合并索引，按 [维护约定](references/knowledge-base.md) 协作。无新知识不制造重复记录，不盲删索引锁。
4. 关闭或卸载本轮授权账号的 COR3 游戏页，保留浏览器、其他标签及登录。后台模式按接入文档清理并验证；用户正在前台使用时不抢占窗口。异常退出也尽力完成这一收尾，未验证成功则明确说明。
5. 只有用户授权定时执行且平台支持时才安排续办。确有后续工作时，按真实刷新、维护结束、任务期限或远征结果安排下一次单次运行。用户要求降低频率时合并临近有效时点，不为无变化状态或短暂远征选择每几分钟唤醒；已接任务期限与到期风险仍需记录，说明合并检查对短暂选择的影响。未知时间说明依据，不能编造精确倒计时。
6. Codex 中使用 `automation_update` 更新本线程已有任务；其他宿主使用其支持的调度接口，没有接口就说明未安排；先读最新完整字段，保留目标线程、名称、提示、通知偏好和其他要求，避免覆盖另一个执行者的新安排。维护 skill 本身不改变游戏日程。核对用户时区与调度时区（如 UTC）、仅一次且在未来、UTF-8 中文与路径正常，重读验证。不用原始 TOML 写入，不新建重复任务。
7. 已验证达到 The Pillar 后停止该账号自动推进并报告。若一个自动任务管理多个账号，只移除已达标账号的后续操作，其余继续；全部负责账号达标后再暂停该任务。其他情况简述本轮进展、具体阻碍、下一时间和网页收尾结果。

## 持续改进

知识库保存具体配装、路线、失败和版本差异；本 skill 只吸收影响决策的稳定方法。新增实测反例先写知识库，再针对性修订流程，避免把一次修复扩大成普遍规律。只有用户授权协调时才跨线程发送消息；共享知识不转移账号控制权。
